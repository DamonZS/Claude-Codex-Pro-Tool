# 供应商模型默认 1M 上下文

## 背景

供应商编辑器目前会让新建或补全的模型显示为空上下文窗口，导致用户需要逐个填写能力声明。

## 目标

- 新建供应商的默认上下文窗口为 `1000000`。
- Codex 模型目录中缺少上下文窗口时，补齐为 `1000000`，并在保存的目录 JSON 中写入该值。
- Codex 模型目录行使用“1M 上下文”复选框，默认勾选。勾选时序列化 `contextWindow: 1000000`；取消勾选时保留 `supports1m: false`，不再写入 1M 上下文字段。
- Codex 原生目录条目在勾选 1M 时写入 `context_window` 和 `max_context_window`；取消勾选时仅写入 `max_context_window`。默认上下文不超过模型最大值；可识别的 Codex 模型沿用内置目录中的 `max_context_window`，未知供应商模型默认最大值为 `1000000`。
- 未配置模型映射时，使用供应商的主模型及模型列表生成目录，不丢失各模型的最大上下文声明。
- 不修改 Claude 供应商的模型映射、1M 标记或默认行为。

## 非目标

- 不改变供应商请求协议、模型路由或远端模型接口。
- 不覆盖已有 Codex 目录中大于零的明确上下文窗口，除非用户明确取消 1M 复选框。
- 不改变供应商明确填写的模型最大上下文值。

## 验收

- 打开新建 Codex 供应商或新增/拉取模型时，模型目录行的“1M”复选框默认勾选。
- 解析缺少 `contextWindow` 的 Codex 目录后，行值和序列化 JSON 均为 `1000000`。
- 勾选时保存 JSON 的条目包含 `contextWindow: 1000000`；取消勾选时包含 `supports1m: false` 且不包含 `contextWindow`。
- 应用 Codex 供应商后，模型目录 JSON 对勾选条目写入独立的 `context_window` 和 `max_context_window`，取消勾选条目只写入 `max_context_window`；无映射时从主模型/模型列表生成目录。
- 映射模型可识别内置 Codex 最大值时保留该值；未知模型的默认最大值为 `1000000`。
- Claude 供应商的模型映射和 1M 标记行为保持原样。
