# 原生与 Multica 执行统一任务看板

## 背景与目标

用户要求移除“我的任务”上方独立的原生子任务列表，将原生子智能体与 Multica
创建的任务一起呈现在原始看板中，并随真实执行进展自动移动到对应列。
本规格覆盖旧 `codex-native-subtasks-in-my-tasks` 的独立区域布局要求。

## 用户行为与 UI

- 保留原始 MyIssuesPage 和卡片/看板/筛选/列表控件，不增加另一套看板。
- 原生子任务用昵称、来源、真实执行状态、更新时间呈现；保留打开子/父会话。
- 每个原生子线程或无 Issue 的执行产生一个稳定的只读投影卡片；已有 Issue 的
  执行映射回原卡片，不再产生重复卡片。无执行的 Agent 定义不虚构任务。
- 待执行/排队→待办，执行中→进行中，完成→已完成，失败/中断/阻塞/未知→阻塞，
  取消→已取消。阻塞卡片须明确显示失败或“状态待确认”等原因，未知不当成失败。
- 执行中间态明确归列：binding_pending、dispatched、waiting_local_directory→待办；
  running、原生 inProgress、cancel_pending→进行中（后者标“取消中”）；
  reconciling、stale、orphaned→阻塞并说明状态待确认。
- 普通未执行 Issue 保留原状态与自定义状态；关联执行的卡片按最新一次执行投影。
- 每 5 秒可见页面刷新；隐藏/离开停止额外轮询。查询失败保留上次完整数据并展示
  过期/重试提示，避免“没有任务”的假空态。
- 首次原生查询降级仍展示成功读取的普通 Issue/执行；有效但过期的原生元数据
  标记状态待确认。已有完整快照后任一来源失败保留上次完整快照并显示过期提示。
- 原生和无 Issue 执行卡片保持原始卡片外观；禁止拖拽/编辑/删除它们改变真实状态。
  点击进入只读详情或现有原生会话打开入口，错误保留页面并可重试。

### 拖动与导航补充（用户实机反馈，以本节为准）

- 用户明确跨列拖动是执行指令：已完成/失败等原生子智能体拖到进行中，复用原线程
  继续执行；拖到待办则进入真实待执行队列，由现有 Codex 调度链路执行。
- 默认继续指令为“继续完成当前任务，检查剩余工作并完成验证；若已全部完成，简要确认结果。”
  不复制父会话消息、不向父会话发送智能体信息。执行留在原子线程，不创建第二模型运行时。
- 复用现有执行绑定/继续/队列接口，必要时给原生线程建立真实绑定，保持看板去重。
  正在运行的任务重复拖动不产生第二次执行；失败要显示反馈并恢复真实归列。
- 排队后的卡片拖到进行中立即派发原排队命令；同一动作重试保留命令键。
  派发结果未知时先读取原线程，确认新 turn 后接管该结果；旧 turn 不冒充新结果，
  不重复启动。刷新到待确认状态仍保留原动作的错误反馈和重试入口。
- 完成、失败、中断等按真实执行状态自动归列；向完成等列拖动不伪造执行结果。
- 原始卡片样式和其他字段的只读约束保持；原生数据库只通过现有原生 API 更新，
  不直接写 SQLite。真实状态变化优先于同列显示排序。
- 点击详情中的打开子会话/父会话必须确认原生页面激活；错误保持详情并可重试。
- 本节的显式执行拖动覆盖前文全面禁止拖拽及投影一律拒绝 mutation 的限制，
  其他编辑/删除/批量字段写入仍拒绝。

## 数据与接口

- 原生数据继续来自只读 `codex_native_agents` query；有界分页最多 500 条近期记录。
- Multica 执行来自 `/multica/executions/list`；以 bindingId、issueId、codexThreadId
  建立关联。排重优先已有 Issue，其次无 Issue 绑定，最后原生线程。
- 同一 Issue 多次执行按 createdAtMs/attempt/id 稳定选择最新执行，旧完成记录不能
  遮盖新排队或运行。合法但未知状态显示待确认。
- Adapter 在筛选、分页、分组、计数之前合并投影；只读详情也来自同一状态来源。
- 虚拟卡片 ID：`codex-native:<threadId>`、`ccp-execution:<bindingId>`。
  Issue.metadata 使用原始 primitive map 携带 `ccp_read_only:true`、
  `ccp_source`、`ccp_execution_state`、`ccp_thread_id`、`ccp_parent_thread_id`、
  `ccp_binding_id`、`ccp_agent_name`（适用时）；卡片标题不复制原生完整 prompt。
- 只读投影一律拒绝 mutation；不写回 Codex 数据库，不创建 Agent 定义或 Issue，
  不触发新执行。原生虚拟身份只用于展示/筛选，不赋予执行权限。
- 实际工作中智能体计数与可见执行状态一致，避免上方显示 0 但看板有运行卡片。

## 技术与交付

改动限于 adapter/查询投影、main/原生呈现、必要原始 UI 适配及 vendor 生成器、
配套测试和验收文档。保留版权与 manifest，生成器是派生源修改的权威入口。
保留所有用户数据、其他页面行为和工作区已有修改，不引入第二执行器。
先投影/真实组件回归测试，再前端流水线、必要 Rust 校验和默认 Release 构建，
最终实机卡片归列、自动变化及父子导航由用户测试（按最新交付要求）；
本轮完成代码收尾和默认 Release 构建，不再自动执行实机验收。
