# 蒸馏子代理、可安装技能包与卡片库

## 背景

当前「蒸馏工作台」只有一个动作：把选中的会话一键蒸馏成一个文本产物，产物留在 CCP 里，用户既不能指定「蒸馏什么、蒸成什么形态」，也不能把产物变成可复用的能力。用户提出三条新需求：

1. 蒸馏要由**子代理**执行，可以接受用户下发的指令（会话蒸馏 / 技能蒸馏 / 踩坑蒸馏），并且能自己判断「该不该蒸馏、该蒸什么、该蒸成什么」。
2. 蒸馏产物要能做成**可安装的 Claude Codex Pro 技能**，用户一键安装到插件中心，其他 CCP 用户也能复用来蒸馏他们自己的会话。
3. 建立**卡片库**：经验 / 踩坑 / 指导 / 项目架构 等都是卡片，由模型自己判断类型并打标签，还能随会话消息增长自动判断「该不该创建卡片」；闪卡编辑是可选的（用户愿意才去编辑）。

参考实作：`H:\xunlei\aitracker-main` 的蒸馏模块，以及用户给出的 `karpathy-guidelines` 技能样例（会话实现的技能形态）。

## 目标

包含：

- 蒸馏子代理：会话内可下发指令的蒸馏入口，支持 `会话蒸馏 / 技能蒸馏 / 踩坑蒸馏` 三类意图，并给出「该不该蒸馏」的判断与理由。
- 技能包产物：把蒸馏结果打包成 CCP 可安装的技能包（带 `SKILL.md`），一键安装到 Codex / Claude 的技能与插件中心，安装后可被其他用户复用。
- 卡片库：卡片的创建、分类、打标签、检索、编辑（可选）、导出；随会话消息增长自动产生卡片建议。
- 上述能力的只读入口与命令层，按 P0（数据与命令）/ P1（UI）/ P2（自动化建议）分层交付。

不包含：

- 云端共享、账号体系、跨用户同步（技能包只落在本机 CCP 数据目录，导出由用户自行分享）。
- 自动修改用户 Codex / Claude 的配置或已有技能。
- 多语言技能包模板、市场审核流程。

## 用户视角

1. 用户在 CCP 的会话里对蒸馏子代理说「把这会话蒸成技能」/「只要踩坑」/「蒸成架构说明」。
2. 子代理判断这条会话值不值得蒸馏，值得就产出对应形态的蒸馏结果，并说明它选了什么类型、为什么。
3. 用户点「做成技能」，CCP 生成一个技能包并显示安装结果（新技能出现在插件中心 / Codex skills 列表里）。
4. 用户打开「卡片库」，看到按类型和标签归类的卡片；可以在会话里让子代理「把这条记成卡片」，子代理自己判断类型与标签；用户也可以事后编辑（可选）。

## 功能要求

F1 蒸馏子代理指令面（P0）

- 支持三类指令意图：`session`（会话蒸馏）、`skill`（技能蒸馏）、`pitfall`（踩坑蒸馏）。
- 请求体接受 `instruction` 文本 + 选中的会话 id 列表；响应给出 `kind`、`reason`（为什么该蒸 / 不该蒸）、`confidence`、以及产物。
- 当子代理判断「不该蒸馏」时，必须返回 `skipped: true` 与理由，不生成产物。

F2 技能包产物与一键安装（P0/P1）

- 产物结构：`<skill-name>/SKILL.md` + 可选 `scripts/`、`references/`。
- `SKILL.md` 必须含 `name`、`description`（触发条件），且描述必须是可直接使用的技能说明，禁止空骨架占位。
- 一键安装：安装到 CCP 技能目录并在插件中心可见；安装前校验目标不存在或允许覆盖；安装结果以命令返回值返回（成功/冲突/失败）。

F3 卡片库数据模型（P0）

- 卡片字段：`id`、`kind`（`experience` / `pitfall` / `guidance` / `architecture` / 其他）、`title`、`body`、`tags[]`、`source`（会话 id / 蒸馏任务 id / 手动）、`createdAt`、`updatedAt`。
- 卡片库落在 CCP 数据目录的单一 JSON 存储，读写走同一模块，禁止直接散写。
- 查询支持按 `kind`、`tag`、关键词过滤，以及分页。

F4 模型判定类型与标签（P0）

- 生成卡片时由模型给出 `kind` 与 `tags`；模型返回值非法时降级为 `kind=experience` 且标签为空，并记录诊断。
- 标签去重、限长、限数量。

F5 会话消息驱动的卡片建议（P2）

- 扫描会话消息（复用现有会话读取链路），按阈值（消息数 / 关键词 / 显式指令）产生「建议创建卡片」的候选，候选带来源会话与理由。
- 建议只入队到卡片库的待确认列表，不自动写库。

F6 编辑可选（P1）

- 卡片编辑是可选操作：不编辑也能正常创建、检索、导出；编辑仅提供改标题/正文/标签/类型。

## UI / 交互要求

- 蒸馏工作台内新增「蒸馏指令」输入与意图选择（会话 / 技能 / 踩坑），提交后显示子代理的判断结果（类型、理由）与产物预览。
- 产物预览区提供「做成技能」按钮与安装结果提示（成功文案 / 冲突提示）。
- 卡片库页面：列表（标题 + 类型标签 + 标签 + 日期）、类型与标签过滤、搜索、新建/编辑弹窗（编辑可选）、导出单卡与整库。
- 建议区：待确认卡片候选列表，可一键接受或忽略；空态与错误态给出明确文案。

## 数据与接口要求

- 新增/复用 Tauri 命令（示意）：
  - `run_distillation_agent(instruction, session_ids) -> { kind, skipped, reason, confidence, artifact }`
  - `install_distillation_skill(package) -> { installed, path, conflict? }`
  - `load_card_library() / save_card(id) / delete_card(id) / export_card(id)`
  - `list_card_suggestions() / accept_card_suggestion(id) / dismiss_card_suggestion(id)`
- 输入校验：空指令、空会话列表、超长文本（沿用现有蒸馏上限）必须有明确错误码与用户可读文案。
- 存储位置：CCP 数据目录内的卡片库 JSON 与技能目录；不得写入用户 Codex / Claude 配置目录。

## 技术约束

- 复用现有蒸馏管线（`crates/claude-codex-pro-core/src/distill_pipeline.rs`、`distill_prompts.rs`、`distill_model_client.rs`）与模型客户端，不新引入依赖。
- 技能包格式对齐 Codex 插件约定：`.claude-plugin/plugin.json` 或 `SKILL.md` 目录结构。
- 前端沿用现有 React + Tauri 命令调用约定（`App.tsx` 的 `call`）。
- 命令层返回值遵循 `ok` / `failed` 构造器风格。
