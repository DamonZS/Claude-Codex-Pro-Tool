# 多客户端提示词、技能与工具资源库

## 背景

原「系统提示词」页只服务 Codex 一条链，且页内嵌的破甲部署面板职责与通用投放重叠。
多个 AI 编码客户端都提供设计上开放的全局指令 / 技能扩展点，CCP 需要一套统一、
可逆、逐目标可见的投放机制。

## 目标

- 页面上勾选客户端，点提示词即可批量投放到全部勾选项。
- 覆盖 7 个本地客户端：Codex、Claude Code、DeepSeek Harness、ZCode、
  WorkBuddy 国际版、WorkBuddy 国内版、Cursor。豆包列出但不可投放。
- 提示词、技能与工具资源由仓库 `Prompt/` 统一维护；CCP 从本仓库固定清单获取资源。
- 技能同样批量安装，按清单管理，可逆卸载。
- 独立源码/二进制工具以版本化工具包提供，用户显式安装到 CCP 管理的数据目录并可卸载。
- 移除页内破甲部署面板，其职责并入投放区。

## 非目标

- 不复制完整上游仓库、Git 历史或无关文件；只收录筛选后的提示词、技能和独立工具包。
- 工具包不得自动执行、注册自启或修改客户端配置；本功能只下载、校验、安装和卸载。
- 缺少明确许可、来源或完整性校验值的资源不得进入可安装清单；研究目录中的资料可仅作外部参考。
- 不实现云端记忆投放（WorkBuddy `memoryBlock`、豆包云端记忆）。
- 不修改供应商、模型、Codex 注入、Claude Desktop 官方文件。
- 不删除 `leila_deploy.rs` 及其命令（仅从 UI 摘除面板）。

## 用户视角

1. 进入「系统提示词」，页面显示统一部署控制台。
2. 在第一个下拉框选择一个客户端；7 个客户端始终列出，已安装目标排在前面，未安装目标置灰不可选。
3. 在第二个下拉框选择来自 `Prompt/index.json` 的版本；悬停或聚焦时显示简介与适配目标。
4. 点击部署后，先投放版本正文，再为同一目标安装资源库中的技能和工具，并逐步显示成功/失败结果。
4. 下次投放相同内容自动跳过，不刷新部署时间。
5. 「还原已勾选」撤销选中目标，「一键全部还原」撤销所有受管目标。
6. 技能区列出远端技能，可安装到已勾选项或卸载。

## 功能要求

### 投放引擎

- 目标注册表：显示名、数据目录候选（按优先级）、注入方式、指令文件相对路径。
- Codex 走 `ManagedFile`：写受管文件 + 设置 `config.toml` 的 `model_instructions_file`。
- 其余 6 个走 `MarkedBlock`：写入全局指令文件，用起止标记块包裹，块外内容不动。
- 首次投放保存基线；重复投放沿用首次基线，不覆盖。
- 内容一致时跳过；内容变化时替换受管块。
- 还原只摘 CCP 写出的内容：`MarkedBlock` 摘标记块，`ManagedFile` 恢复原配置行或删除新增行。
- CCP 写出的内容被外部改动时拒绝还原并说明差异。
- 标记块必须恰好有一对顺序正确的起止标记；缺失、重复、嵌套或顺序错误时不得猜测并写回，必须保留原文件并报告冲突。
- 还原时校验目标目录、指令文件和配置文件仍对应投放时记录的路径与受管内容；目录替换、符号链接改指或受管配置行被外部改动时，不得写入新位置或覆盖外部值。
- 单目标投放作为事务处理：指令文件、Codex 配置和部署状态任一写入失败时，恢复已改写的文件；无法完成恢复时保留可恢复记录并明确报告，不得留下“已成功”状态。
- 兜底清扫独立于主流程执行，结果单独上报。
- 未检测到的目标返回「未安装」，不创建目录。
- Codex 的 `model_instructions_file` 与系统提示词页共用；该键正指向系统提示词页受管
  文件时拒绝投放，避免双写。

### 内容库

- 清单地址写死：`https://raw.githubusercontent.com/DamonZS/Claude-Codex-Pro-Tool/main/Prompt/index.json`。
- 清单校验：提示词路径必须位于 `prompts/` 且为 `.md`；技能路径必须位于 `skills/`，
  必须包含 `SKILL.md`，且所有文件路径必须落在该技能目录内。
- 所有清单路径与技能名均按路径组件校验；拒绝绝对路径、`..` 逃逸及解析后越过预期根目录的符号链接，不以字符串前缀代替目录包含关系。
- 下载缓存落在应用状态目录；网络不可用时返回离线状态，页面提示仅可投放内置模板。
- 技能文件先下载到独立暂存目录；全部文件下载、大小限制和清单校验成功后再整体发布到缓存。任一文件失败时不得暴露部分新版本，也不得破坏上一个完整缓存版本。
- 技能按清单安装：只移除清单内且指纹未变化的目录；用户自有同名目录一律不动。
- 技能目标安装采用暂存与提交；复制或状态记录失败时恢复此前目录和状态，失败后不留下与磁盘不一致的已安装记录。
- 工具清单条目必须有稳定 ID、版本、来源仓库/修订、许可证标识与许可证文件、支持平台，以及每个文件的相对路径、大小和 SHA-256；工具文件必须位于 `Prompt/tools/<id>/`。
- 工具清单缺来源、许可、哈希或包大小时拒绝下载/安装；UI 展示这些元数据和安装状态。
- 工具包逐文件下载到独立暂存目录，限制单文件与总大小；每个文件 SHA-256 全部匹配后再整体原子发布。
- 工具包按清单文件指纹安装到应用状态目录 `prompt-tools/<id>/<version>`；不写 PATH，不启动工具，不运行包内脚本。
- 工具卸载只删除 CCP 记录且文件指纹未变化的版本目录；外部修改时保留文件并报告冲突。更新失败时保留之前完整版本。
- 包内保留来源和许可证文件；不包含完整上游仓库、仓库历史、无关文档或依赖缓存。

## UI / 交互

- 顶部统一部署区块：客户端目标下拉、版本下拉、版本简介、部署、还原和刷新内容库。
- 未安装目标与豆包置灰不可勾，并标注原因（未安装 / 需云端，暂不支持）。
- 内容库离线时显示告警条。
- 技能和工具不再作为独立页面区块；部署日志必须列出本次版本关联的技能、工具安装和校验步骤。
- 页面保留一处统一部署日志，不再显示“环境与资源安装日志”“技能库”“独立工具包”旧标题。
- 保留原有提示词卡片网格、分类筛选、编辑与 GitHub 同步能力。

## 数据与接口

新增 Tauri 命令：

- `list_client_deploy_targets` → `{ targets: ClientDeployTargetRow[] }`
- `deploy_prompt_to_clients(request: { targetIds, content })` → 逐目标结果数组
- `restore_client_deploy(request: { targetIds })` → 逐目标结果数组；`targetIds` 为空表示全部
- `fetch_prompt_index` → `{ online, prompts, skills, installed, tools, installedTools }`
- `fetch_prompt_content(promptId)` → `{ promptId, content }`
- `install_skills_to_clients(request: { targetIds, names })` → 逐项结果数组
- `remove_installed_skills(request: { targetIds, names })` → 逐项结果数组
- `install_tool_package(toolId)` → `{ toolId, version, installPath, sha256 }`
- `remove_tool_package(toolId, version)` → 逐项结果；已修改的受管文件保留并报告冲突

批量命令一律返回 `results` 数组加成功/失败计数，单个失败不影响其余目标。
`CommandResult` 使用 `serde(flatten)`，因此 payload 必须是结构体，不得用裸字符串。

## 技术约束

- 新增 core 模块 `client_deploy.rs`、`prompt_library.rs`；`Prompt/` 目录与生成脚本。
- 复用 `settings::atomic_write`、`paths`、`http_client`。
- 工具包采用清单枚举的普通文件，不执行归档解包；不引入新运行时依赖。
- 默认 Release 输出到仓库根目录 `target/release`。

## 交付范围

- `Prompt/` 目录结构、`Prompt/README.md`、`scripts/build-prompt-index.mjs`。
- CI：`pr-build.yml` 与 `security-audit.yml` 增加清单一致性校验。
- core 两个模块及其测试；Tauri 命令；前端类型、actions、页面与样式。
- 工具包元数据、精选资源清单和来源/许可证归属文件；禁止打包完整上游项目。
- 本 spec 与对应 acceptance。
