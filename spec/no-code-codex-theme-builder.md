# Codex 无代码 DIY 主题工作台

## 背景

当前主题中心支持下载官方主题和导入本地主题包，但用户自行设计主题仍需要手工编写 `theme.json` 与 CSS。多数用户只希望选择背景并调整玻璃效果，不应被要求理解 Codex DOM、配色体系、主题清单或压缩包结构。首版 DIY 工作台暴露了主色、背景色、表面色、文字色、外观模式和密度，用户很难判断这些参数之间的对比度关系，且背景被整页铺设后缺少 Dream Skin 主题主视觉区域的层次。

## 目标

- 在主题中心提供“DIY 主题”入口，通过精简的可视化控件创建 Codex 主题。
- 提供与控件同步的实时预览，不要求用户编写任何代码。
- 根据背景图自动推导明暗外观、强调色、背景色、表面色和文字色；界面密度与文字大小固定使用 Codex 原生默认值。
- 参考现有 Dream Skin 主题，将背景作为有边界的首页主视觉区域；主视觉使用低对比环境铺底和位于中央、保持完整比例的清晰主图，侧栏、内容面板和输入区使用分层玻璃表面。
- 支持重新编辑由 DIY 工作台创建的主题，并保留原主题 ID。
- 保存结果继续通过现有主题包校验、临时目录、原子替换、Mutation Journal 和回滚流程。
- 保持官方主题下载、本地导入、应用、删除、背景设置和 Codex 注入行为不变。

## 非目标

- 不提供任意 CSS、JavaScript、Renderer 脚本或远程 URL 编辑器。
- 不尝试解析或可视化编辑第三方导入主题及官方下载主题的任意 CSS。
- 不在保存时自动重启 Codex，不修改供应商、模型、汉化、会话或凭据配置。
- 不把用户选择的背景图上传到网络。

## 用户流程

1. 用户在主题中心点击“DIY 主题”。
2. 工作台以左右分栏打开：左侧为外观控件，右侧为稳定尺寸的 Codex 界面预览。
3. 用户设置主题名称、说明、图片布局、玻璃透光度、模糊强度和圆角。作者不在工作台中展示或编辑；明暗模式、配色、界面密度与文字大小由系统自动处理。
4. 用户可选择本地 PNG、JPEG 或 WebP 背景图，也可移除背景图；界面只展示文件名和本地预览，不展示完整路径。
5. 用户点击“保存到主题中心”后，Core 生成受控主题包并走现有导入事务。成功后主题立即出现在主题列表，但不会自动应用。
6. 用户也可点击“保存并应用”，保存成功后应用该主题，并提示重启 Codex 生效。
   如果主题已保存但应用失败，明确提示“已保存、未应用”并关闭本次新建工作台，避免重试时生成重复主题；用户可从主题卡片再次应用。
7. DIY 主题卡片提供编辑按钮；再次打开时恢复上次设置。当前主题允许编辑，替换成功后 generation 增加并提示重启。

## 功能要求

### 可视化设置

- 名称必填，1 至 80 个字符；说明最多 400 个字符。作者字段仅为旧主题包格式兼容保留，工作台不展示作者输入，新主题使用固定默认作者，编辑旧主题保留原作者。
- 工作台不显示主色、背景色、表面色、文字色、浅色/深色、密度或文字大小控件。
- 背景存在时，Core 对降采样像素进行确定性分析，自动推导外观模式和安全调色板；无背景时使用稳定的 Codex 中性默认调色板。
- 自动文字色与主要表面必须保持可读对比；低饱和背景使用系统蓝作为强调色，不能生成灰色或不可见的操作状态。
- 界面密度固定为 Codex 默认舒适密度，文字大小固定为原生 100%，不改写原生布局节奏和字号；兼容字段继续保留但保存时统一归一化为默认值。
- 玻璃透光度面向用户显示为 10% 至 92%，数值越高背景越清晰；内部表面不透明度与透光度反向换算。模糊限制为 0 至 48px，圆角限制为 0 至 16px。
- 实时预览必须使用当前 Codex 首页结构，展示左侧项目与会话栏、右侧主工作区、中央品牌视觉和底部输入区；不得继续使用旧版顶部栏、多卡片或建议按钮布局，控件变化不能改变编辑器整体尺寸。
- 关闭编辑器前若存在未保存修改，需要二次确认。

### 图片布局

- 使用三段互斥控件选择图片布局：`fullscreen`（全屏透明背景）、`banner`（上方长条）和 `card`（中央大卡片）；默认使用 `card`。
- `fullscreen` 将图片作为整个 Codex 画布的 `cover` 环境背景，不在中央重复显示图片；侧栏、主工作区和输入框必须按玻璃透光度显露背景。
- `banner` 保持 Codex 原生首页结构，在首页标题上方显示宽幅横条，使用稳定焦点的 `cover` 裁切，不把图片铺到全屏。
- `card` 保持 Codex 原生首页结构，在中央显示有边界的大卡片，使用 `contain` 保留完整图片，不把图片铺到全屏。
- 未选择背景图时，三种模式都回退到原生中央图标和自动纯色画布；切换模式不创建、复制或删除图片。
- 实时预览、生成 CSS 和主题卡片 PNG 必须使用同一个布局字段和相同语义。

### 自动主视觉与玻璃层

- 背景图以低对比环境画布铺在玻璃表面之后，使透光度变化能够真实显露同一张图片；中央品牌视觉同时显示使用 `contain`、保持完整比例的清晰主图，行为与当前 Codex 首页结构一致。
- 主视觉区域根据自动外观生成方向性可读遮罩，但遮罩只能作用于环境铺底，不能覆盖或显著压暗中央主图；标题、状态和操作在亮图或暗图上均清晰。
- 侧栏、主工作区和输入区使用由同一自动调色板生成的玻璃层，透光度变化必须真实显露其后的环境图片，而不是只改变一个不可见变量。
- 无背景时使用自动调色板生成克制的纯色主视觉，不伪造图片。

### 背景图

- 仅允许本地普通文件，不接受符号链接、目录或 URL。
- 仅支持真实格式与扩展名一致的 PNG、JPEG 和 WebP。
- 单图最大 8 MiB，像素总数不得超过 100,000,000。
- 新建主题未选择背景时使用纯色背景；编辑时未重新选择则保留原背景；“移除背景”明确删除原背景。
- 背景图只复制进本地主题包，不记录来源绝对路径。
- 用户选图后由 Core 立即校验并返回压缩预览；编辑已有主题时按需读取原背景预览，主题列表不常驻传输大图。

### 生成与编辑

- 新建主题 ID 由 Core 自动生成，使用 `ccp-diy-*` 命名空间并保证本地唯一，用户无需填写。
- DIY 设置作为结构化元数据写入主题 manifest；自动生成的模式和颜色作为内部兼容数据保留，普通主题没有该元数据，因此不显示编辑入口。
- Core 使用固定、受审计的 CSS 模板生成样式，用户输入只能进入经过范围或格式校验的变量。
- 生成包至少包含 `theme.json`、`theme.css` 和 `preview.png`；有背景时增加本地背景资源。
- 预览图由 Core 根据设置和背景生成，不要求前端写临时截图文件。
- 编辑 DIY 主题使用现有替换流程并保留上一版本；禁止通过 DIY 接口覆盖默认主题、官方主题或普通导入主题。
- 编辑请求必须携带打开工作台时的完整性标识；保存时若主题已被其他窗口更新，拒绝覆盖并要求重新打开。
- 保存失败不得改变当前主题、已有主题文件或 generation。

## UI 与交互

- “DIY 主题”是工具栏中的图标加文字按钮，优先级高于“制作指南”，不替代“新建主题”。
- 工作台使用单个大尺寸模态层，不做卡片嵌套；表单与预览在宽屏左右分栏，窄屏改为单列并保持可滚动。
- 不显示模式、密度、色板或颜色输入。使用滑块表达透光度、模糊、圆角和字号，图标按钮用于关闭和移除背景。
- 底部固定操作栏包含“取消”“保存到主题中心”“保存并应用”。
- 保存或背景校验期间整个表单不可编辑，防止请求完成后丢失期间修改。
- DIY 主题卡片提供编辑图标和 Tooltip；默认主题、官方下载主题和普通导入主题不显示编辑按钮。
- 覆盖加载、保存中、校验失败、背景读取失败和空背景状态；所有状态不能只依赖颜色表达。

## 数据与接口

新增 Core 结构与 API：

```rust
CodexThemeDiySettings
CodexThemeDiyInput
CodexThemeDiyBackgroundPreview

CodexThemeStore::save_diy_theme(input: CodexThemeDiyInput)
    -> anyhow::Result<CodexThemeSummary>
CodexThemeStore::preview_diy_background(path)
    -> anyhow::Result<CodexThemeDiyBackgroundPreview>
CodexThemeStore::diy_theme_background_preview(theme_id)
    -> anyhow::Result<CodexThemeDiyBackgroundPreview>
```

`CodexThemeManifest` 增加可选 `diy` 字段，`CodexThemeSummary` 返回可选 DIY 设置。`CodexThemeDiySettings.image_layout` 保存三种图片布局；旧 manifest 缺失该字段时按 `card` 读取，保持向后兼容。新增 Tauri 命令：

```text
save_codex_diy_theme(input)
preview_codex_diy_theme_background(source_path)
load_codex_diy_theme_background(theme_id)
```

前端文件选择仍由 Tauri dialog 插件完成，命令只接收用户明确选择的本地路径；前端不直接依赖任意本地文件 URL 权限。错误结果沿用现有 `CommandResult`。

## 技术约束

- 继续使用 React、TypeScript、Lucide、现有 Button 和 Tauri 调用封装，不新增 UI 库。
- Core 负责所有安全校验、ID 生成、CSS 生成、预览图生成和事务化安装，前端只维护表单与实时预览。
- 不写入系统临时目录之外的散落文件，不在日志、通知或前端展示完整背景路径。
- 不覆盖当前未提交改动，不改变主题包现有格式版本和非 DIY 主题兼容性。

## 交付范围

- Core DIY 数据结构、校验、主题包生成、背景保留/移除、预览生成和测试。
- Manager Tauri 命令、类型、动作、DIY 工作台、主题卡片编辑入口和样式。
- 规格、验收、README 与主题制作文档更新。
- 默认 `target/release` 最新构建及本地视觉验收。
