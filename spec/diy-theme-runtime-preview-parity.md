# DIY 主题预览与 Codex 运行时一致性

## 背景

DIY 主题工作台已经提供全屏背景、上方长条和中央大卡片三种实时预览，但当前 React 预览、Core 运行时 CSS 与 Core 主题卡片 PNG 分别维护布局和透明度参数。三套参数发生漂移后，用户在工作台中确认的图片亮度、工作区透明度、主视觉尺寸、标题字重和输入区层次无法在真实 Codex 中复现。浅色主题通用兼容样式还会继续追加到 DIY 主题运行时载荷，使非全屏 DIY 图片被再次铺到主工作区。

## 目标

- 真实 Codex 中的 DIY 主题以工作台实时预览为视觉基准。
- 全屏、上方长条和中央大卡片三种布局在运行时 CSS、主题卡片 PNG 与实时预览中保持相同语义和关键参数。
- 已保存的 DIY 主题在下次生成活动载荷时自动使用修复后的模板，不要求用户重新保存。
- 下载主题、普通导入主题、默认主题及其兼容样式保持原样。

## 非目标

- 不重新设计 DIY 工作台界面或改变用户可配置字段。
- 不修改主题 Loader、注入协议、主题包格式或下载主题 CSS。
- 不把主题卡片 PNG 改为真实 Codex 截图，也不改变现有图片安全校验。
- 不修改供应商、会话、插件、汉化、模型或管理工具外观。

## 用户视角描述

1. 用户在 DIY 工作台选择背景图片及图片布局。
2. 用户以右侧实时预览确认图片尺寸、裁切方式、透明表面和标题层次。
3. 保存并应用后，真实 Codex 首页应按相同布局显示，不再出现主图被放大、工作区过度透明、输入区过暗或浅色兼容层把图片额外铺满页面的问题。
4. 主题中心生成的 PNG 应使用相同布局比例，便于用户从主题卡片识别实际效果。
5. 用户下载或导入的非 DIY 主题不因本次修复发生任何 CSS、兼容层或运行时载荷变化。

## 功能要求

### 全屏透明背景

- 背景图片继续以 `cover`、居中、原始亮度铺满主题根画布。
- 左侧栏继续使用完全不透明的自动表面色。
- 主工作区使用自动背景色的 78% 不透明表面，与实时预览一致。
- Composer 使用自动表面色的 96% 不透明表面，与实时预览一致。
- 原生首页图标保持实时预览中的圆形轮廓，不被通用卡片圆角改成方形。
- 所有相关区域禁用 `backdrop-filter`，不新增全屏渐变或颜色蒙层。

### 上方长条

- 图片主视觉使用 `cover`，居中裁切，固定 `8px` 圆角。
- 图片主视觉使用与实时预览相同的 `0 10px 24px rgb(0 0 0 / 0.18)` 阴影。
- 运行时主视觉宽度为 `min(88%, 470px)`，高度为 `108px`。
- 主题卡片 PNG 按其 960x600 基准画布使用与实时预览等价的宽高比例和位置。
- 图片不得通过浅色主题兼容层再次成为主工作区全屏背景。

### 中央大卡片

- 图片主视觉使用 `contain`，居中显示完整比例，固定 `8px` 圆角。
- 图片主视觉使用与实时预览相同的 `0 10px 24px rgb(0 0 0 / 0.18)` 阴影。
- 运行时主视觉宽度为 `min(76%, 360px)`，高度为 `138px`。
- 主题卡片 PNG 按其 960x600 基准画布使用与实时预览等价的宽高比例和位置。
- 图片不得通过浅色主题兼容层再次成为主工作区全屏背景。

### 共同行为

- 首页标题字重使用 450，与实时预览一致。
- 首页主视觉组不再沿用 Codex 的底部对齐逻辑；三种模式都从主工作区顶部 64px 处开始，图片变高时标题随图片向下移动，而不是图片向上漂移。
- 图片主视觉使用独立的 `background-color`、`background-image`、`background-position`、`background-size` 和 `background-repeat` 长属性，避免 Chromium 丢弃包含图片层和纯颜色层的无效简写。
- 无背景时继续显示原生首页图标，不改变三种布局的回退行为。
- 运行时 CSS 不增加全局 `dialog`、`menu`、`button`、`input` 或 `select` 覆盖。
- 已安装 DIY 主题的活动载荷由 manifest 中的 `diy` 设置重新生成，不依赖保存时遗留的旧 CSS。

## 数据与接口要求

- 不新增前端字段、Tauri 命令或 manifest 字段。
- `CodexThemeDiySettings.image_layout` 仍是唯一布局来源。
- `CodexThemeStore::active_theme_payload_for_state` 必须区分 DIY 与非 DIY：
  - DIY 使用受控 `render_diy_css` 模板，且不追加面向下载主题的浅色运行时兼容层。
  - 非 DIY 继续读取自身 `entry_style`，并保持现有官方主题及浅色主题兼容行为。
- `write_diy_package` 继续同时生成 `theme.css` 与 `preview.png`。

## 技术约束

- 修改范围限定在 `crates/claude-codex-pro-core/src/codex_theme.rs` 及对应测试；除规格和验收文档外，不要求修改 Manager 前端。
- 不修改 `LIGHT_THEME_RUNTIME_COMPAT_CSS` 的内容，只调整它对 DIY 主题的适用条件。
- 不修改 `assets/inject/codex-theme-loader.js`。
- 保留工作区内现有供应商相关未提交改动。
- 使用测试先锁定参数，再修改生产实现。

## 交付范围

- DIY CSS 模板与实时预览关键参数一致。
- DIY PNG 生成器与三种布局的比例和透明表面一致。
- DIY 与非 DIY 运行时兼容样式隔离测试。
- Core 定向测试、前端检查、工作区相关构建以及真实 Codex 运行态证据。
