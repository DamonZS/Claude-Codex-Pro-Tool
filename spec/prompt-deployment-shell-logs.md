# 系统提示词部署控制台与实时日志

## 背景

系统提示词页面可以检测客户端环境，并投放/还原提示词、安装/卸载 Skill 和工具包。破甲部署已有逐行运行日志，但页面曾移除破甲控制台，用户既看不到目标环境、资源校验和回滚状态，也只能在任务结束后看到诊断日志。

## 目标

- 在系统提示词页面提供统一部署控制台和固定展开、可刷新、可滚动的“运行状态”日志窗口。
- 移除顶部当前提示词状态/启用方式/使用方式区域，以及部署结果卡片和重复资源路径摘要。
- 记录客户端环境检测、提示词投放/还原、Skill 安装/卸载、工具包安装/卸载、破甲检测/部署/回滚的真实步骤与结果。
- 破甲已有逐行日志继续实时显示；其他文件操作明确标注为 CCP 文件操作步骤，不伪装成外部 Shell 子进程输出。
- 日志不得包含提示词正文、密钥、令牌或环境变量值。

## 用户视角

用户在“系统提示词”页面可直接查看“运行状态”窗口中的最近步骤、客户端/资源路径、成功或失败结果，并刷新日志。窗口始终展开，不提供折叠操作。执行上述任一操作时日志自动刷新；破甲部署运行中继续显示实时逐行输出。

## 功能要求

- 使用现有诊断日志作为持久化来源，并用结构化事件表示阶段、目标、路径和结果。
- 日志面板按时间展示可读行，处理旧格式/无效 JSON 行时仍保留原文。
- 成功与失败状态在同一日志区域可辨识；不另显示重复的部署结果卡片或资源安装路径摘要。
- 操作完成或失败后更新页面日志；破甲使用现有 `leila-deploy-log` 事件。
- 页面停留在系统提示词页时定时刷新诊断日志，确保未产生 Tauri 实时事件的文件操作也能在执行期间出现。
- 离开页面时停止轮询；回到页面后重新加载环境、资源和日志状态。
- 不在日志中记录提示词内容、认证信息或完整进程环境。

## 技术约束

- 复用 `read_latest_logs` 与 `append_diagnostic_log`。
- 不启动额外 shell，不将文件操作伪装成终端命令；对没有子进程 stdout 的操作显示实际 Rust 操作步骤。
- 保持现有操作确认、投放和回滚逻辑不变。

## 交付范围

- 规格与验收文档。
- Tauri 操作日志事件、系统提示词页终端面板及其类型/动作接线。
- 定向后端测试、前端检查与默认 Release 构建。
