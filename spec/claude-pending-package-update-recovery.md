# Claude 待完成包更新的启动恢复

## 背景与目标

本机 Claude 已注册版本为 2.2553.1.0，启动时 Windows 尝试注册已暂存的 2.9939.2.0；AppXDeploymentServer 404/401 事件确认更新在 PackagesInUseClosed 阶段以 0x80070005 退出，MSIX 和 AppsFolder 均未形成 Claude 进程。目标是修复这条已确认的启动故障，而非绕过 Windows 的包验证。

## 用户视角与范围

用户点击现有“启动/重启 Claude”。普通启动流程失败后，只在本次操作产生同一 Claude 包家族的待更新注册拒绝事件时，执行一次 Windows 官方注册恢复，然后重新尝试现有包激活入口。按钮、外层界面、供应商、账号、配置和 macOS 行为保持现状。

## 功能与数据要求

- 同时满足启动无进程、MSIX 拒绝码为 0x80070005、本次操作期间出现同一包家族的 AppXDeploymentServer 404 事件、事件目标版本高于当前注册版本，才执行恢复。
- 通过 Get-AppxPackage 读取当前用户的 Claude 包身份；事件解析使用 XML EventData 字段，不依赖中文消息匹配。
- 使用 Add-AppxPackage -RegisterByFamilyName -MainPackage 的官方恢复途径，关闭权限仅限目标包，不扫描或直接执行 WindowsApps 二进制。
- 不下载、移除包、不改权限、不改官方安装文件、不写用户配置或会话数据。
- 恢复最多一次；恢复命令失败时保留真实失败结果，不重复恢复。
- 恢复成功后仍复用现有进程与可见窗口探测。没有进程或窗口时不得返回普通成功。
- 诊断只记录恢复阶段和脱敏错误码，不输出完整事件消息或凭据。

## 交付与风险

修改限于 core 的 claude_desktop.rs、定向测试及匹配验收文档。官方注册修改当前用户的包注册状态，保留已安装包与用户数据；若 Windows 官方注册仍拒绝访问，交付真实错误和系统修复入口，不宣称本机启动已恢复。
