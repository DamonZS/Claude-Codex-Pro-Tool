# 修复 Claude Desktop 供应商创建与切换失败

## 背景

Windows 下更新已存在的 Claude Desktop 配置文件时，原子替换可能返回 `os error 183`，导致供应商创建或切换失败。

## 目标

- 让已有配置文件可以被可靠覆盖更新。
- 保持临时文件写入、替换和失败清理的原子写入流程。
- 不改变 Claude Desktop 配置结构和供应商切换业务逻辑。

## 验收

- 原子写入对同一目标文件连续写入两次后，第二次内容可读且完整。
- Claude Desktop 供应商切换路径继续通过 `atomic_write` 写入配置。
- 相关 Rust 单元测试通过。
