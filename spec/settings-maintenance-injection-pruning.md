# 维护、设置与 Codex 注入精简

## 背景和目标
维护和设置页存在固定禁用控件、重复修复入口，以及混入 Codex 增强矩阵的其他产品功能。本次落实用户六项精简要求，保留真实调用链和旧配置兼容。

## 用户视角与功能要求
- 维护页删除固定关闭的卸载数据开关、三个禁用路径按钮、入口管理中的重复修复入口。检查区保留有效的修复快捷方式与修复后端。
- 设置页删除修复后端按钮。
- Codex 矩阵删除供应商同步、供应商配置、会话删除、Markdown 导出、会话项目移动、Codex 目标、Claude 覆盖、CLI 包装器、本地工作流条目。
- 供应商能力独立展示，不再显示同步开关；新配置及缺字段配置默认启用供应商同步和供应商配置，已有显式值保持兼容。
- Claude、CLI、本地工作流仅从矩阵移除，保留现有独立页面和能力，避免删除用户正在使用的功能。
- 会话删除、Markdown 导出、项目移动、Codex 目标旧字段保留读取，但不作为前端注入触发条件。
- 保留插件入口、插件市场、时间线、阅读视图、位置恢复、Zed、工作树、原生菜单、Fast、图片覆盖等真实增强。
- 强制插件安装、Zed 远程打开/项目记录/设置同步、上游工作树、原生菜单默认关闭。已保存的显式开关不迁移、不覆盖。
- 三项已在 renderer 固定关闭的会话旧功能默认关闭；客户端能力摘要仅展示真实的时间线能力。

## UI / 交互
沿用现有透明液态玻璃、外层导航、面板组件和保存动作。未加载设置时继续禁用操作，不增加依赖或新接口。

## 数据、接口与技术约束
继续使用 BackendSettings / SettingsStore / saveSettings。兼容字段及后端有效命令保留；Rust Default 和 serde 缺字段默认保持一致。不修改用户配置、官方客户端文件、供应商内容、采集与会话管理实现。

## 交付范围
screens.tsx、客户端能力摘要、settings.rs、launcher.rs、定向回归测试、本规格与验收、默认 target/release 应用及本地验证/回滚证据。
