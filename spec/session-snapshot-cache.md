# 会话与蒸馏工作台的持久化快照

## 背景

会话页和蒸馏工作台的数据来自本机会话扫描：冷启动要逐行读取数 GB 的 Codex / Claude /
WorkBuddy 会话文件，本机实测一次全量扫描 70–117 秒。用户每次重启应用后打开这两个页面都要重新
等待，体验远差于 AITracker——后者页面打开只读已持久化的快照，扫描在后台完成。

本规格把扫描结果持久化到应用数据目录，页面先读快照，过期后后台刷新。

## 目标

- 应用重启后，会话页与蒸馏工作台**直接读持久化快照**，不再同步全量扫描。
- 快照超过 5 分钟视为过期：先返回旧数据，后台线程刷新，刷新完成后下一次读取拿到新数据。
- 扫描按文件增量：解析结果按 `(path, size, mtime)` 缓存（内存 + 磁盘），未变化文件直接复用，只重新解析新增/修改的文件。
- 启动时（Tauri `setup`）若快照缺失或过期，立即在后台预热。
- 进程内缓存快照，连续页面命令不重复解析 JSON。
- 扫描/刷新全局单飞：启动预热与页面命令不会同时扫描同一批文件。

## 非目标

- 不做 SQLite 归一化索引库（AITracker 的 `sessions/usage_*` 表属于后续优化）；本规格的增量停留在「按文件复用解析结果」层。
- 不改变扫描器、解析逻辑与数据来源。
- 不持久化会话正文。
- 不改前端页面结构与交互。

## 功能要求

1. 快照文件（应用数据目录 `~/.claude-codex-pro/aitracker/cache/`）：
   - `usage-snapshot-v1.json`：`savedAtMs` + 会话页所需的 usage 快照与能力快照。
   - `workbench-snapshot-v1.json`：`savedAtMs` + 蒸馏工作台会话列表与 Skill 安装目标。
   - 写入使用临时文件 + 原子替换；解析失败视为无缓存并重建。
2. 读取顺序：进程内缓存 → 持久化快照 → 同步扫描（仅当两者都不存在）。
3. 过期阈值 5 分钟；过期读取不阻塞，触发后台刷新。
4. 后台刷新完成后清空进程内缓存，下一次读取加载新快照。
5. 同一时刻只允许一个扫描/刷新任务；页面命令在快照缺失但预热进行中时等待该任务，而不是重复扫描。
6. 快照损坏、字段缺失或版本不符时回退到同步扫描并重写，不得让页面命令失败。

## 技术约束

- Rust/Tauri 现有架构，复用 `spawn_blocking`、`CommandResult` 与现有扫描函数。
- 快照只存现有结构体（`LocalUsageSnapshot`、`AitrackerSnapshot`、工作台会话行），不新增数据库。
- 不阻塞 UI 线程；刷新在独立线程执行。
- 默认 Release 可执行文件仍需可构建。

## 交付范围

规格、验收、Rust 快照缓存与单测、启动预热接线、构建验证。
