# 验收标准：Codex 无代码 DIY 主题工作台

对应规格：`spec/no-code-codex-theme-builder.md`

## 通过标准

### 创建与编辑

- 主题中心存在“DIY 主题”按钮，点击后打开可视化工作台。
- 用户不编写 JSON、CSS 或颜色值即可配置全部规定字段，并看到同步实时预览；工作台没有作者输入。
- 保存后生成新的 `ccp-diy-*` 主题并出现在主题列表中，不自动应用。
- “保存并应用”先完成安全保存，再应用返回的真实主题 ID，并提示重启。
- 保存成功但应用失败时明确呈现部分成功，不允许原新建草稿重试后重复生成主题。
- DIY 主题卡片显示编辑按钮；重新打开后恢复名称、说明和全部外观设置，旧主题作者元数据保持不变但不在工作台展示。
- 编辑已有 DIY 主题保留 ID、增加版本，并通过现有替换事务保留上一版本。
- 普通导入主题、官方主题与默认主题无法通过 DIY 命令覆盖，也不显示 DIY 编辑入口。

### 校验与安全

- Core 拒绝空名称、超长字段和越界数值；提交中的模式、颜色和密度不能绕过自动推导结果。
- 相同背景和效果参数重复生成的自动外观与调色板稳定一致；低饱和背景回退到可识别的系统蓝强调色。
- 自动文字色与主要表面具有可读对比，明亮和暗色背景均不能生成不可见文字或控件。
- 新主题 ID 由 Core 生成且本地唯一，不能为 `default`，不能覆盖其他主题。
- 生成 CSS 来自固定模板，输入不可能产生 `@import`、远程 URL、脚本或未限定作用域的自定义片段。
- 背景图执行普通文件、符号链接、大小、格式、扩展名、解码和像素上限校验。
- 主题包通过现有 manifest、CSS、图片、路径、大小与完整性校验后才进入正式目录。
- 保存失败不改变现有主题、当前主题 ID 或 generation，不残留活动 Journal 或 DIY 暂存目录。
- 两个窗口同时编辑同一 DIY 主题时，后提交的过期草稿被完整性标识拒绝，不能静默覆盖先提交结果。

### 背景与预览

- 新建时可选择或不选择背景图；编辑时不重新选择会保留原图，点击移除后生成包不再包含背景。
- 前端只显示背景文件名，不显示绝对路径。
- 用户新选图片和再次编辑已有背景均通过 Core 按需返回真实图片预览，不使用主题截图冒充背景，也不要求开放任意本地文件读取权限。
- Core 生成有效 PNG 预览，主题卡片可正常显示。
- 工作台不再显示手动主色、背景色、表面色、文字色、外观模式、密度和文字大小控件；保存结果的文字大小固定为原生 100%。
- 选择背景后，实时预览使用 Core 返回的自动模式与调色板；无背景时使用稳定默认值。
- 实时预览和主题卡片 PNG 使用当前 Codex 首页结构：左侧项目与会话栏、右侧主工作区、中央品牌视觉和底部输入框，不得显示旧版顶部栏、多卡片或建议按钮布局。
- 选择背景后，同一图片既作为玻璃层后的低对比环境画布，也作为中央保持完整比例、清晰且水平垂直居中的主图；环境铺底和可读遮罩不能盖住主图，预览、生成 CSS 与主题卡片 PNG 的结构保持一致。
- 玻璃透光度可调范围覆盖 10% 至 92%；调整到 92% 时，侧栏、主工作区和输入框后面的环境图片必须清晰可辨，调整到低透光度时表面应明显遮蔽环境图；模糊和圆角变化即时更新。
- 图片布局提供“全屏透明背景、上方长条、中央大卡片”三个互斥选项，默认选中中央大卡片，切换后实时预览立即更新且整体尺寸不跳动。
- 全屏模式只显示一层全画布 `cover` 背景，中央保留原生图标；顶部横幅只在标题上方显示宽幅裁切图；中央大卡片只在中央显示保持完整比例的图片。
- 保存并重新编辑后恢复上次图片布局；旧 DIY 主题没有 `image_layout` 时按中央大卡片显示并可正常保存。

### 交互与布局

- 工作台宽屏左右分栏，最小支持窗口下改为单列且内容可滚动。
- 底部操作栏稳定可见；保存中禁用重复提交和其他主题写操作。
- 保存与背景校验期间名称、效果滑块和背景控件均不可继续修改。
- Escape、关闭按钮和点击遮罩可关闭；有未保存修改时需要确认。
- 所有输入有可读标签，滑块显示当前数值与单位，键盘焦点清晰。
- 浅色与深色 Manager 外观下文字、表单、菜单和预览均可读，无遮挡或溢出。

### 回归

- 官方主题下载判重、删除保护、本地 ZIP/目录导入、应用、恢复默认和 Manager 背景保持可用。
- 现有非 DIY manifest 在缺少 `diy` 字段时仍可读取和应用。
- Codex 注入、供应商、模型、汉化、会话和其他页面行为不变。

## 验证方式

```powershell
cargo fmt --check
cargo test -p claude-codex-pro-core --manifest-path Cargo.toml codex_theme -- --nocapture
npm --prefix apps/claude-codex-pro-manager run check
npm --prefix apps/claude-codex-pro-manager run vite:build
cargo test -p claude-codex-pro-manager --manifest-path Cargo.toml --test windows_subsystem -- --nocapture
cargo build --release
```

手动验证：

- 新建无背景 DIY 主题并保存，确认使用稳定自动调色板、卡片预览和未启用状态。
- 新建带明亮与暗色背景的 DIY 主题，确认自动外观、强调色、文字对比正确，实时预览红框主视觉、生成主题和主题卡片 PNG 均可看到完整居中的清晰主图；编辑效果但不重选背景，确认背景保留。
- 编辑同一主题并移除背景，确认版本更新、上一版本可回滚且背景被移除。
- 使用“保存并应用”，重启 Codex 后确认生成样式生效。
- 将玻璃透光度分别调整到低值和高值，确认所有玻璃层存在清晰可见的透光差异。
- 在浅色、深色及最小窗口下检查工作台布局、焦点、滚动和文字可读性。

## 必需证据

- 上述自动化命令真实结果。
- Core 创建、编辑、背景保留/移除、非法输入和非 DIY 覆盖保护测试。
- DIY 工作台宽屏、窄屏、浅色和深色截图。
- 默认 `target/release/claude-codex-pro-manager.exe` 的路径、大小和更新时间。

## 非目标

- 不验证任意 CSS 在线编辑。
- 不要求将用户主题上传到 GitHub 或主题市场。
- 不要求自动重启 Codex。
