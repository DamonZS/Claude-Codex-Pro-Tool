# 验收标准：Manager Liquid Glass 外壳落地

## Agent Control Glass 增强验收

- 侧栏、顶部栏、页面标题、通用面板、命令面板和菜单具有一致的折射边缘、内高光与环境景深，不只在概览页生效。
- 背景图的明暗轮廓可透过外壳和导航辨认；表格、表单、日志和长文本仍使用清晰表面。
- 深色与浅色模式的正文、次要文字、输入值和菜单项均清晰，不对文字使用 blur、filter 或低透明度蒙层。
- 请求链路节点具有可辨认的前后层次和悬停反馈，但不持续动画；减少动态模式下取消位移。
- 现有路由、顶部操作、供应商切换、主题切换和业务 IPC 契约测试保持通过。

验证对象：`spec/manager-liquid-glass-shell.md`

## 通过标准

### 1. 外壳与侧栏

- 深色、浅色和跟随系统均可使用，切换后不丢失现有页面状态。
- 侧栏展开宽度为 200-216px，折叠宽度为 56px；折叠后图标可用、文字隐藏、悬停名称可见。
- 侧栏选择持久化，重启前端后仍保持用户选择。
- 页面背景没有装饰网格、光球或持续动画。
- 侧栏背景可辨认环境图的明暗与轮廓，不呈现为完全不透光的黑色块。

### 2. 材质与可读性

- 外壳、侧栏、顶部栏、命令面板和 Toast 具有可辨识的玻璃透光、模糊、细边缘与内高光。
- 表单、表格、日志和长文本区域为高不透明表面，复杂背景不穿透正文。
- 浅色模式标题、正文、次要文字、输入值和菜单项清晰，无模糊、低对比度或残留硬编码深色块。
- 浅色供应商编辑器外壳与配置区块具有可辨识的半透明材质和边界，输入框、下拉框、文本域与模型选择按钮使用清晰的深色文字、灰绿色边框和高不透明背景，并具有明确的悬停与焦点状态。
- 卡片不套卡片，控件和文字在最小窗口不重叠、不溢出。
- 概览、供应商、客户端、主题、提示词、会话、扩展、维护和设置页均使用同一套玻璃 Token 与边缘高光；不存在只有概览页有材质、其他页面恢复纯色旧 UI 的情况。
- 表单、表格、日志和长文本保持清晰高不透明度，不以牺牲可读性换取透光。

### 3. 顶部布局与动作语义

- 标题后依次排列“Codex / Claude”、搜索和当前供应商，上下文控件作为一组靠左，不被推到窗口中部或隐藏；首次加载默认选择 Codex，源码和运行状态均不存在不可见的“全部”范围。
- 当前供应商以“状态点 + 供应商名 + 当前 + 下箭头”的紧凑一体控件展示，供应商名过长时只截断名称，“当前”和箭头始终可见；可展开真实供应商列表，选择后复用 `switchSupplierProfile`，不新增另一套配置写入逻辑。
- 供应商数量超过浮层高度时仅中间列表滚动，所有供应商均可通过滚轮、触控板或键盘访问，标题和底部“管理供应商”操作不被裁掉。
- 代理健康状态只通过当前供应商控件最前方的红绿状态点表达，顶部不存在重复的“代理在线/离线”独立控件或孤立状态点。
- 三个启动动作在可用宽度下保持右侧完整显示；窄屏时可仅显示图标并保留 Tooltip，不遮挡上下文控件。
- “Claude 一键汉化”和“测试连接”使用成功绿色；普通启动、编辑和导航按钮不误用成功色。

### 4. 顶部更新入口

- 应用启动后只静默执行一次现有更新检查，不阻塞首屏。
- `updateAvailable` 为真时，在“启动/重启 Codex”之前显示亮绿色、无背景框、粗描边下载箭头；否则不显示。
- 悬停或键盘聚焦显示当前版本、最新版本、更新说明和状态。
- 点击后调用真实 `perform_update`，下载阶段、百分比和字节数来自现有进度事件。
- 下载中按钮不可重复触发；完成或失败后状态可理解并可再次操作。
- 入口有可访问名称、焦点环、`aria-live` 和 `progressbar` 语义。

### 5. 行为回归

- 三个顶部动作、命令搜索、Codex/Claude Agent 筛选、供应商切换和供应商内代理状态点继续工作。
- 仅新增主题背景设置和恢复命令，未改变更新参数、下载源、安装器、供应商协议或注入行为。
- 未修改供应商、会话、记忆、扩展、主题、提示词或注入业务逻辑。

### 6. 响应式与高 DPI

- 960x640、1280x800、1440x900、1920x1080 与 3840x2160 下无关键控件遮挡、文字溢出或不可达滚动区。
- 高 DPI 下边框、图标和文字清晰；更新箭头不因缩放变细或出现背景框。
- 3840x2160 下工作区利用可用画布，不被压缩为中央 2200px 小窗口；背景不通过 transform 放大导致模糊，SVG 图标和 1px 边缘保持清晰。
- `prefers-reduced-motion` 下非必要动效关闭。

### 7. 主题高清背景

- 主题包声明 `--ccp-theme-manager-background` 时，Manager 使用对应的本地 PNG、JPEG 或 WebP 作为环境背景。
- 未声明专用变量但声明 `--ccp-theme-art` 时，Manager 兼容使用该图片；两者同时存在时专用变量优先。
- 默认主题、无背景主题和读取失败状态使用内置深浅色背景，不残留上一主题图片。
- 应用主题、恢复默认主题和替换当前主题后无需重启 Manager 即可刷新背景；Codex Renderer 的生效规则保持不变。
- Manager 不接收主题 CSS、远程 URL、根类或根属性，不因主题背景污染表单、菜单、输入框或其他原生交互。
- 3840x2160 下背景覆盖完整且不拉伸变形；960x640 下不造成文字遮挡或水平溢出。
- 主题中心存在可见的“设置背景”入口，文件选择器只显示 PNG、JPEG 和 WebP。
- 1920x1080 边界尺寸可通过校验；任一边低于 1920x1080、伪造扩展名、损坏格式或超过大小上限时文件被明确拒绝，旧背景保持不变。
- 合格图片通过临时校验与原子写入后立即成为 Manager 背景，并在 Manager 重启后保持；原始图片不被修改。
- “恢复主题背景”会清除用户选择并正确回退到当前主题自带背景或内置背景。
- 主题中心预览显示用户背景后，应用外壳必须立即显示同一张图片；切换至其他导航及重启 Manager 后仍保持，不能继续显示内置背景。
- 自定义背景使用独立 `<img>` 背景层，存在时内置 `::before` 背景不可遮盖它；无自定义背景时该图片层不存在且内置深浅背景正常回退。

## 必需验证

```powershell
npm --prefix apps/claude-codex-pro-manager run check
npm --prefix apps/claude-codex-pro-manager run vite:build
cargo fmt --check
cargo test -p claude-codex-pro-manager --manifest-path Cargo.toml --test windows_subsystem -- --nocapture
cargo test --workspace
cargo build --release
```

## 完成证据

- 上述命令的真实结果。
- 默认 `target/release/claude-codex-pro-manager.exe` 的本次修改时间和路径。
- 原生 Tauri Manager 的深色、浅色、展开侧栏、折叠侧栏和更新入口截图。
- 至少一张使用 1920x1080 或更高分辨率主题背景的截图，以及默认背景回退截图。

## 失败条件

- 仅修改静态效果稿，没有落到真实 Manager。
- 更新入口使用模拟数据、重复实现下载逻辑或无更新时仍显示。
- 只执行 Vite 构建，未生成默认 `target/release` 可测试应用。
- 任何现有路由、顶栏动作、更新下载或业务页面入口失效。
- 截图泄露 API Key、Token、敏感地址、私密会话全文或无关绝对路径。

## 6. 概览控制台

- 概览首屏具有四项真实 KPI、供应商路由列表、中央三段链路拓扑、右侧智能诊断和底部事件时间线，整体层级与确认的深浅色参考图一致。
- 供应商列表来自当前 `relayProfiles`；概览供应商路由只显示 Codex 与 Claude 两个筛选按钮且没有“全部”，切换范围和点击供应商会同步更新列表、拓扑与 Inspector，不修改磁盘配置。
- “设为当前”复用现有供应商切换动作；“编辑配置”进入对应供应商编辑器；“测试连接”调用 `test_relay_profile`，不调用模型发现接口。
- API Key 始终显示为遮罩状态；时间线仅显示事件名称、分类、结果和时间，不显示日志 detail 中的凭据、URL、请求正文或路径。
- 无延迟、请求量、成功率或事件数据时显示“未检测”“暂无事件”等真实空态，不出现参考效果稿中的模拟数字。
- 请求与事件时间线的图例、泳道、刻度、事件内容、空态和说明字号均不低于 10px，主要泳道和事件名称不低于 12px；在 1280x800、1440x900 和 1920x1080 下无需放大界面即可辨认。
- 公告、记忆开关、Claude 开发模式和原有修复动作仍可从概览访问。
- 960x640 下三栏按可滚动顺序重排，1440x900 下保持三栏，3840x2160 下内容宽度、文字和边框清晰且不过度拉伸。
